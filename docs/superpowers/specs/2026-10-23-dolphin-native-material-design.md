# Dolphin-Native Material Correction Design

## Intent

Make the existing Qt Widgets ReasonNotes candidate feel native beside Dolphin
under Reason's actual `qt6ct-style -> Kvantum` desktop environment. Dolphin is
the authoritative visual reference. Preserve ReasonNotes' current layout,
editing, note model, Sync drawer, navigation, and application behavior.

## Goals

- Replace the custom translucent top-level sheet with Kvantum's native
  `PE_Widget` window material by making the existing tested native path the
  default.
- Remove the editor body's forced `#2C3539` application-owned fill and derive
  its readable writing surface from the active system palette/native style.
- Keep the sidebar and content area visually related through native palette
  roles, with only restrained hierarchy where Dolphin itself separates its
  navigation area.
- Reduce the conspicuous screen-coordinate background patches and the visual
  disconnect of the dark editor panel.
- Produce an independently identifiable candidate for controlled owner visual
  review; visual acceptance remains Reason's decision.

## Non-goals and anti-goals

- No layout, navigation, Sync drawer, note model, editor behavior, localization,
  Android, or synchronization redesign.
- No production/candidate installation replacement and no writes to either
  existing personal notes repository.
- No global qt6ct, Kvantum, Hyprland, Noctalia, or KDE Connect changes.
- No new application-owned theme, copied Dolphin layout, maximum-opacity rule,
  speculative gradients, grain masks, or compositor tuning.
- The new default rendering path may not contain or apply literal HEX, RGB,
  RGBA, or HSL colors; fixed background opacity; manually invented tints; or
  custom fallback palettes. Window, sidebar, card, search, title, and editor
  surfaces must come from the active Qt `QStyle` and `QPalette` supplied by
  qt6ct/Kvantum and must adapt automatically when the system theme changes.
- No interactive launch without Reason's explicit authorization.

## Existing evidence

- The screenshot supplied on 2026-10-23 shows the current candidate beside
  Dolphin. ReasonNotes exposes broad blue/gray background transitions through
  the whole window, while Dolphin presents a coherent native slate material.
  ReasonNotes' deep green editor sheet is also substantially darker and more
  detached than Dolphin's content area.
- Prior controlled tests established that the broad patches follow desktop
  coordinates and are not generated by Qt child gradients or the blur request.
- The existing source-only native Kvantum path delegates the top-level sheet to
  `PE_Widget`; it reduced broad composited variation by about 75%, while
  increasing raw alpha from roughly 194 to 240. The previous rejection was
  based on preserving experimental glass depth; that priority is superseded by
  Dolphin-native integration.
- Qt Quick versus Widgets does not cause the patches when the submitted RGBA
  material is the same.

## Chosen approach

Use the existing native Kvantum implementation as the default top-level paint
path, retaining the current custom path only as a source-controlled diagnostic
comparison if doing so stays simple and cannot leak into the default. Remove
the forced editor color and expose active palette/Kvantum styling through the
editor. Preserve native control painting and avoid broad stylesheets or new
custom paint layers.

Sidebar separation, cards, search, and editor surfaces must delegate to native
style/palette behavior without fixed alpha or calculated application tints. If
the active native style cannot provide a requested distinction, report that
limitation rather than simulate Dolphin with hardcoded values. The initial
implementation should let native material ownership establish continuity.

## Files and behavior boundaries

- `src/reasonnotes_widgets/main_window.py`: select native Kvantum window
  material by default; do not alter splitter, navigation, controller, or Sync
  behavior.
- `src/reasonnotes_widgets/editor_page.py` and/or
  `src/reasonnotes_widgets/visuals.py`: remove the hard-coded solid editor
  surface and retain the unmodified active style/palette.
- `src/reasonnotes_widgets/material.py`: change only pane-fill defaults needed
  for native continuity; the default path delegates surfaces to `QStyle` and
  `QPalette` without color or opacity literals. Preserve focus readability and
  existing widget contracts.
- `linux-app/reasonnotes_widgets.py`: keep diagnostics explicit and ensure the
  packaged default selects the Dolphin-native material.
- Focused rendering and behavior tests: update assertions from fixed custom
  colors to native palette/style delegation, uniformity, contrast, and unchanged
  editor/navigation behavior.

## Verification and safety

1. Record the installed candidate release/launcher and existing candidate-note
   hashes before any build; never write those paths.
2. Resolve or safely account for the earlier production generated-view writes
   before requesting a live launch. A launch is blocked until command-line root
   routing and all resolved repository paths are proven candidate-only.
3. Run focused offscreen tests first with disposable persistent HOME/XDG/data
   roots and copied read-only qt6ct/Kvantum configuration.
4. Build a new immutable candidate under a new persistent staging directory;
   do not activate or install it.
5. If Reason separately authorizes visual runtime, launch only the new staged
   candidate with disposable notes and matched qt6ct/Kvantum configuration.
   Capture ReasonNotes and Dolphin under controlled monitor, scale, wallpaper,
   geometry, and position conditions.
6. Report native-style chain, material measurements, screenshots, tradeoffs,
   and production/candidate data hashes. Stop for owner visual acceptance.

## Acceptance for this corrective milestone

- Focused tests and build succeed for an independently identifiable candidate.
- Offline rendering shows native Kvantum ownership of the top-level material,
  no forced `#2C3539` editor sheet, readable controls/text/focus states, and no
  behavioral changes.
- Existing installed candidate, personal candidate notes, production app/data,
  Android, synchronization state, and global configuration remain unchanged.
- Controlled live screenshots are supplied only if separately authorized;
  otherwise the exact visual-runtime gate is reported.
- Android synchronization remains explicitly unfinished.

## Approaches considered

- **Chosen: native Kvantum foundation plus palette-native editor.** Best match
  to Dolphin and reuses measured, tested source already present.
- Native window with current editor: rejected because the dark detached panel
  remains one of the owner's named defects.
- Denser custom glass: rejected because it continues application-owned painting
  and obscures rather than directly follows the native reference.
